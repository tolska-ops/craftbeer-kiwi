## Recently done (context only - safe to trim once this feels stale)

- ✅ **Supabase secret-key 401 issue resolved** (27 July) - this had been sitting blocked for a week. Turned out not to be a Supabase platform bug: `@supabase/server`'s secret-key auth mode requires a *named* key (`auth: "secret:<name>"`), and both Edge Functions had been written with just `auth: "secret"` - no name - which the SDK couldn't resolve, producing a generic 401 regardless of which valid key was sent. Fixed by referencing the actual named key (`brewery_sync_v2`) in both functions and redeploying. No support ticket needed in the end. See `craftbeer-kiwi-decisions.md` for the full troubleshooting story.
- ✅ **`brewery-discover` successfully tested end-to-end for the first time** (27 July) - `{"found":20,"inserted":12,"skipped":8}`. Surfaced two real discovery-quality issues, both now documented in `craftbeer-kiwi-automation-plan.md`: Places' search returns bars/pubs alongside genuine breweries, and `place_id`-only dedup can miss a second listing for the same physical business. All 12 new rows manually triaged: 6 excluded as bars, 1 duplicate corrected, 5 confirmed as genuine breweries/taprooms (including 3 ambiguous "brand-operated venue that functions like a bar" cases resolved by local knowledge rather than automatable rules).
- ✅ **`venue_type` field added** (27 July) - new column on `breweries` (default `'brewery'`, also used as `'bar'`), tested first in `craftbeer-kiwi-DEV` before being added to production. Frontend map query now filters on `venue_type = 'brewery'` alongside the existing `is_active = true`. Deliberately a string field rather than a boolean, since Andy flagged a possible future "pubs & bars" layer as worth keeping the door open for.
- ✅ **Geolocation fallback bug fixed** (27 July) - both failure paths (`!navigator.geolocation` and the `getCurrentPosition` error callback) previously set the user-location marker to a hardcoded Wellington CBD coordinate; now they leave `userLocation` as `null`, so the marker simply doesn't render rather than showing a misleading fake position. Also switched to `enableHighAccuracy: true, maximumAge: 0, timeout: 10000` to reduce the chance of a stale/cached low-accuracy fix being used. Directly addresses the 26 July Blenheim visitor report.
- ✅ **Zoom-dependent brewery name labels** (27 July). Added a Mapbox native symbol layer (`<Source>`/`<Layer>`) that renders brewery names as text once zoomed in past `minzoom={14}` — deliberately set higher than the initial `13` after Andy found the lower threshold too crowded; `14` lines up with the existing pin-click `flyTo` zoom level, so labels tend to appear right around where users naturally land anyway. Built entirely on top of the existing pin/clustering system without changing it: pins remain the same React `Marker` components with the same theming as before. Two real bugs caught and fixed during testing in `craftbeer-kiwi-DEV` before this ever touched production: (1) labels initially showed under breweries that were actually hidden inside a numbered cluster bubble - fixed by building the label data from the already zoom-aware `clusters` array (filtered to exclude clustered points) instead of the raw `breweries` array; (2) long brewery names (tested with "Garage Project Wild Workshop", "Duncan's Brewing Company") were confirmed to wrap cleanly onto two lines without breaking layout or collision detection. Legibility was tuned after Andy found the initial text hard to read: bumped to bold text (`text-font`), a larger size (14 vs 12), and a thicker white halo (2.5 vs 1.5) - confirmed working well on both Light and Dark themes. Known remaining limitation (logged separately above): since pins are separate React components outside Mapbox's own rendering system, a label can still visually overlap a *neighbouring pin* even though it correctly avoids overlapping other *labels*.
- ✅ **Environment indicator (DEV badge)** (27 July). A small red "DEV" badge now shows in the header whenever `VITE_APP_ENV` isn't set to `production` - visible on local dev pointed at `craftbeer-kiwi-DEV`, invisible on the real production site. Built specifically after a near-miss where schema SQL was almost run against production due to a dashboard mix-up.
