## Not started

- ⚪ **Geolocation fallback bug.** Found 26 July: a visitor in Blenheim saw the user-location marker placed at the Wellington CBD fallback coordinates instead of their actual location. Suspect cause: `navigator.geolocation.getCurrentPosition` called without options, so the browser may be returning a cached position or silently hitting the permission-denied fallback. Fix: pass `{ enableHighAccuracy: true, maximumAge: 0, timeout: 10000 }` as the options argument, and confirm the permission-denied path isn't being hit unexpectedly. Needs a desktop session to view/edit `App.jsx`.
- ⚪ **Mapbox GL symbol-layer migration for pins themselves.** The new brewery name labels (see Recently done) use Mapbox's native symbol layer, but the pins are still separate React `Marker` components that Mapbox's collision system has no awareness of - so a label can still visually clash with a *neighbouring* pin, even though labels correctly avoid colliding with each other. Confirmed as a real (minor) limitation during testing, not fixed. Full fix means migrating pins to Mapbox's symbol-layer system too (icons + text together), which would need pre-rendered themed pin images per brewery/colour rather than the current live SVG/CSS `Marker` approach - a bigger job, deferred for now since the label-vs-label collision was the main problem and that's solved.

## Recently done (context only - safe to trim once this feels stale)

- ✅ **Zoom-dependent brewery name labels** (27 July). Added a Mapbox native symbol layer (`<Source>`/`<Layer>`) that renders brewery names as text once zoomed in past `minzoom={14}` — deliberately set higher than the initial `13` after Andy found the lower threshold too crowded; `14` lines up with the existing pin-click `flyTo` zoom level, so labels tend to appear right around where users naturally land anyway. Built entirely on top of the existing pin/clustering system without changing it: pins remain the same React `Marker` components with the same theming as before. Two real bugs caught and fixed during testing in `craftbeer-kiwi-DEV` before this ever touched production: (1) labels initially showed under breweries that were actually hidden inside a numbered cluster bubble - fixed by building the label data from the already zoom-aware `clusters` array (filtered to exclude clustered points) instead of the raw `breweries` array; (2) long brewery names (tested with "Garage Project Wild Workshop", "Duncan's Brewing Company") were confirmed to wrap cleanly onto two lines without breaking layout or collision detection. Legibility was tuned after Andy found the initial text hard to read: bumped to bold text (`text-font`), a larger size (14 vs 12), and a thicker white halo (2.5 vs 1.5) - confirmed working well on both Light and Dark themes. Known remaining limitation (not fixed, logged separately below): since pins are separate React components outside Mapbox's own rendering system, a label can still visually overlap a *neighbouring pin* even though it correctly avoids overlapping other *labels* - full fix would mean migrating pins into Mapbox's symbol-layer system too, deferred as its own item.
- ✅ **Environment indicator (DEV badge)** (27 July).
